# Accessible org charts

Three D3.js prototypes that show an organization as a radial chart that doesn't depend on a mouse. They are static HTML pages built with accessibility as a requirement.

## Why

Org charts are usually pictures. A screenshot of boxes and lines tells a screen reader user nothing, and large charts are hard to use with a keyboard or at high zoom. These prototypes show the same information in forms that work with a keyboard, a screen reader and a text search.

## The charts

- **`radial_dendogram.html`**: a collapsible radial tree. Each node announces its name, title, department and whether it is expanded.
- **`radial_org_chart.html`**: a radial sunburst you can drill into.
- **`radial_sunburst.html`**: an extended sunburst that loads `org_data.csv` and falls back to embedded data when the file can't be fetched.

From the code, what they share:

- arcs are keyboard-focusable and carry `aria-label`s with name and title;
- a "Select a name" control jumps to a person, and a nested list of the same hierarchy is built next to the chart, so the structure is also available as text;
- colours are set through CSS variables.

`index.html` links to all three, and to the dashboard below.

## The dashboard (`dashboard/`)

A fuller org chart that pairs an accessible tree with a decorative sunburst:

- **Left: the primary interface.** A WAI-ARIA tree of everyone, with search. Arrow keys move, Enter or Space selects a person and focuses the chart on them. `+` / `−` zoom the chart toward the focused person, and `0` resets.
- **Right: a sunburst.** It's hidden from screen readers because the tree carries the same information. Click a slice to focus on that person, or click the centre to go up a level. When a branch has fewer levels than the whole org, its rings widen so it still fills the same circle, which leaves room to label more names. Each team is centred under its manager. A name appears only when it fits inside its slice with padding on every side; otherwise it stays hidden until you zoom in far enough. A **Chart labels: Names / Titles** switch above the chart chooses whether slices show names or job titles (shortened, e.g. "VP" or "Mgr.", and wrapped onto up to three lines when needed). The choice is remembered in that browser, and everything else works the same in both modes.
- **Zoom in intervals.** Scrolling magnifies toward the pointer, and about every five wheel notches the branch under the pointer expands one reporting level. Scrolling out past 100% steps back up. The `+` / `−` keys and the on-screen buttons follow the same intervals, and screen readers hear each change.
- **Easter eggs.** Type `years` in the search box for a tenure chart, or `hierarchy` for a tree diagram.

Its data is generated:

```bash
cd dashboard
python3 make_dashboard_data.py   # writes org_data.csv and tenure_data.js (seeded)
```

Both generated files are committed so the dashboard works as soon as the folder is served. If `org_data.csv` can't be loaded (for example when the page is opened from disk), the page shows a small embedded sample org and says so.

Browser tests (Playwright) cover zoom, focus, label fitting and search:

```bash
npm install
npx playwright test
```

## Data

All data is **synthetic**. The dashboard uses `dashboard/make_dashboard_data.py` (see above). `radial_dendogram.html` builds a random fictional org in the page each time it loads. The other two use a fictional "Example Publishing Co." org generated by `make_synthetic_data.py` with a fixed seed from common first and last names, so any resemblance to a real person is coincidence.

```bash
python3 make_synthetic_data.py   # writes org_data.csv (node_id, manager_id, name, department, title)
```

The generated `org_data.csv` is not committed. `radial_sunburst.html` loads it if you generate it and serve the folder over HTTP; otherwise, and when opened from disk, the pages use the small demo dataset embedded in each file.

## Run it

```bash
python3 -m http.server 8000
# open http://localhost:8000/
```

D3 v7 loads from the d3js.org CDN.

## Status

These are prototypes and have not been through a formal accessibility audit. They have not been verified against WCAG, and no conformance is claimed. Keyboard, screen reader, 400% zoom and forced-colours testing is still to do. Issues and test reports are welcome.
